# Security Policy

## Supported Versions

Security fixes are applied to the active development branch and then merged to stable release branches.

| Version | Supported |
| ------- | --------- |
| develop | Yes       |
| main    | Yes       |
| older branches | No |

## Reporting a Vulnerability

Please do not open public issues for potential vulnerabilities.

Report security issues using one of these methods:

1. Preferred: GitHub private vulnerability reporting for this repository.
2. Fallback: Open a regular issue only if the report contains no exploit details, secrets, or reproduction steps that increase risk.

When reporting, include:

- Affected component and file paths
- Impact and threat model
- Reproduction steps or proof of concept
- Suggested remediation if known

## Response Targets

- Initial triage response: within 72 hours
- Status update cadence: at least every 7 days until resolved
- Fix target for confirmed high severity issues: as soon as practical

## Safe Harbor

Good-faith security research and responsible disclosure are welcomed. Avoid privacy violations, service disruption, and data destruction.
